# 研究数据划分与使用规范

确认日期：2026-09-22。适用于因子挖掘、策略研究及工程验收。

本文汇总此前的 A/B/C 约定和本次确认的策略开发、验证安排。本文将新策略任务的数据用途按本次确认更新；历史运行日期、已有合同、原始证据和结果保留原样。数据类别、字段和覆盖情况另见[本地数据总览](本地数据总览.md)。

## 1. 本次确定的整体做法

本次确定的完整流程为：

**因子 A 开发／B 验证 → 策略 A＋B 开发 → 原 C 内部验证 → 冻结完整策略 → 模拟账户最终前向验证。**

| 环节 | 当前确定的数据安排 | 用途 |
|---|---|---|
| 因子探索开发 | A：[2022-08-01, 2024-08-01) | 保持原因子研发流程 |
| 候选因子验证 | B：[2024-08-01, 2025-08-01) | 验证冻结候选，不回传用于同一轮因子搜索 |
| 策略开发 | A＋B：[2022-08-01, 2025-08-01) | 形成、评估和优化完整策略 |
| 策略内部验证 | 原 C：[2025-08-01, 2026-08-01) | 历史验证与研发诊断，登记已有暴露 |
| 完整策略最终前向验证 | 策略冻结并启动模拟测试后新产生的行情 | 在模拟账户检查后续表现和实时执行链路 |

历史日期均为 UTC、左闭右开。上表是默认研究划分；策略研究入口现按合同显式日期读取，不再强制上述固定区间。因子挖掘仍执行其固定A/B规则。

因此，策略端有三个层次：**开发 → 开发阶段内部验证 → 模拟账户最终前向验证**。内部验证结果可以用于选择规则或参数；一旦用于选择，它就属于研发证据，不能同时充当最终测试。

这里的“开发／训练”包括选择因子、组合权重、窗口、方向、阈值、买卖条件和仓位，不限于训练机器学习模型。

## 2. 原有 A/B/C 的定义

原规划依据：[因子挖掘 Agent 改造 Plan 第 6 节](../plans/因子挖掘Agent改造Plan.md)、[多年因子挖掘配置](/Users/stellan/量化投资/experiments/factor_mining/long_history_20260919_setup/README.md)。

| 名称 | 原定用途 | 多年配置日期，UTC，左闭右开 |
|---|---|---|
| A：因子探索开发段 | 构想、计算、评估、优化，记录全部尝试 | [2022-08-01, 2024-08-01) |
| B：候选因子验证段 | 固定候选批次、公式、方向、期限和检验规则后，验证因子并判断入池研究价值 | [2024-08-01, 2025-08-01) |
| C：完整策略最终测试段 | 完整交易策略冻结后的最终测试 | 名义区间 [2025-08-01, 2026-08-01) |

这些日期来自特定多年配置，历史其他合同仍按各自记录解释。不能把任意任务的第二段数据自动称为上述 B 段。

原规划已经明确：B 一旦参与因子筛选，就参与了后续完整策略的研发，因此仍需要留出最终测试。因子挖掘不能查看 B 表现后反复修改，再把同一 B 称为修改后因子的独立验证；其读取入口也不使用 C。

**名义 C 已有暴露。** 既有记录指出，2026 年 4—7 月曾参与开发或验证，整个名义 C 不能作为完整、未触碰的最终测试集。其名称、较晚日期或重新建一个任务，都不能恢复独立性。本次将原 C 明确用于策略内部验证，最终测试改为冻结后进入模拟账户的前向验证。

## 3. 策略端如何使用历史数据

| 层次 | 做什么 | 结果是否可以反馈优化 | 结论范围 |
|---|---|---|---|
| 策略开发集（A＋B） | 因子组合、交易规则、成本与仓位设计；有模型时用于拟合 | 可以 | 开发证据 |
| 策略内部验证集（原 C） | 按时间检验候选，比较规则、参数、成本和阶段表现 | 可以，保留全部尝试 | 开发阶段的选择与稳定性证据 |
| 模拟账户最终前向验证 | 用新产生的行情运行冻结策略，检查账户与执行 | 改策略须记录新版本及新的测试起点 | 前向表现和执行证据；模拟成交不能等同实盘 |

策略开发统一使用 A＋B。完成因子验证后，将 B 的策略开发用途登记；因子 B 的筛选结果属于完整策略已经接触过的研发信息。

但这种复用有明确边界：

- B 对原先冻结因子的验证记录保留；后续用途另行登记。
- 策略端使用 B，不代表允许将 B 结果回传因子挖掘的 A 搜索循环，并继续把原 B 当作新因子的独立验证。
- 若因子已根据 B 被选中，再把 B 切出一部分作为策略内部验证，只能用于开发诊断，不能声称它独立于整个因子筛选过程。
- 原 C 已确认用于策略内部验证；因已有开发／验证暴露，其独立性有限。结果如用于修改或挑选策略，须保留尝试记录，不能再称为干净的最终测试。

新策略任务应在合同中写明实际日期和数据既往用途，并核对区间覆盖；策略入口不会因为日期偏离上表而拒绝运行。内部验证可以重复执行，每次结果单独保存；比较结果时需确认各次输入和候选是否相同。

所有历史回测仍只使用当时可得的数据形成信号和持仓。若以后增加滚动验证，再确定各窗口和选择规则；不因本次确定了数据用途而宣称该能力已经实现。

## 4. 模拟账户最终前向验证

完整策略完成历史开发与内部验证、满足预先声明的进入条件后，冻结并接入模拟账户。测试使用启动后新产生的行情，不以回放原 C 代替前向验证。

开始前固定：信号和计算窗口、买卖规则、仓位和风险限制、费用假设、策略及代码版本，以及测试时长、所需交易数量和通过／停止标准。模拟平台、账户和开始日期也应明确记录；这些具体设置目前尚未确定。

验证同时覆盖两方面：

- 策略在后续新行情中的收益、回撤、成本和风险表现。
- 实时数据、信号、下单、成交、持仓及账户核算能否稳定衔接。

如根据前向结果修改策略，登记新版本、变更原因和新的测试起点。修改前后的成绩分别保存，不能拼接成同一个冻结版本的结果；纯技术故障修复也需保留证据并说明是否影响信号或成交。

模拟成交、滑点和流动性与实盘可能不同，模拟测试通过不等于实盘收益或成交效果相同。本文确认验证路线，不代表模拟账户已接通或已启动。

## 5. 社区策略与因子策略的关系

因子挖掘产出的是候选信号及其证据。经过因子 B 验证后进入创意池，仍需要策略开发和完整策略最终测试。

社区链接、用户输入或市场观察产生的策略可以直接进入策略研究，不要求先伪装成单因子或通过横截面 IC 门槛。它们同样遵守策略开发、内部验证和最终测试的分工。

各路线使用适合自身问题的指标：因子检验预测关系，策略检验含成本的交易与账户表现。共享数据管理原则，不代表共用同一套准入指标。

## 6. 工程验收与正式研究的命名

工程验收用于检查信号、成交、账本、资金费、数据保存与流程交接是否正确。可以使用明确登记过的历史样本，但必须标注其既往用途。

工程任务中的 `development_start / validation_start / validation_end` 只描述该任务的开发和验证区间。后续文档和沟通称其为“工程开发区间／工程验证区间”，不简称为全项目 A/B。

`engineering_complete` 表示计算完成；`passed_declared_checks` 表示是否满足该合同的数值门槛。二者都不自动代表正式研究准入、模型自主研究完成或完整策略最终测试通过。

## 8. 每次研究需要写清的信息

正式运行前，在任务合同和数据使用记录中写清：

1. 研究对象、来源和用途：因子开发、因子验证、策略开发、策略内部验证、模拟账户最终前向验证或工程验收。
2. 数据来源、市场、币种、字段、粒度、UTC 起止日期和预热范围。
3. 区间既往用途，是否影响过因子筛选、规则设计、参数选择或候选淘汰；未知部分标为未知。
4. 开发与内部验证的时间划分；哪些结果允许反馈优化，哪些候选和判断规则需要预先冻结。
5. 预测标签是否跨段、信号何时可用、下一时点如何成交，以及缺失、插补和资金费事件如何处理。预热只提供过去输入，不将未来标签或验证收益带回开发。
6. 实际读取记录、输入快照或可追溯数据版本、候选、评价结果和失败／恢复记录。

数据独立性按实际选择过程判断：没有拟合模型、只看报告、换 Agent、改运行 ID，都不等于数据没有参与研发。

## 9. 已确定与尚待落实

**默认研究设计：** 因子 A 开发／B 验证保持不变；策略示例使用 A＋B 开发、原 C 内部验证；完整策略的最终测试仍需模拟账户前向观察。策略程序接受其他合同日期，因此其输出是否符合此设计须查看实际合同。

**尚待确定：** 各策略的内部验证门槛和进入模拟账户的条件、模拟平台与账户、启动日期、测试时长、交易数量及通过／停止标准。前向测试规则需在开始前确定，不能根据成绩事后选择结束日期。

**接口实施状态（2026-09-22）：** 新增共享数据用途规则，正式因子行情／成员读取强制 A/B 日期，正式策略开发及内部验证读取强制 A＋B／原 C 日期；策略目录查询也受同一边界约束。工程用途允许显式小样本。策略请求／记录和因子输入诊断携带用途；历史数据接口不接受最终测试阶段。

真实日期策略合同示例位于 `examples/strategy_research/research/`；原工程合同和历史运行不改写。`research-data-policy` 显示默认区间；`strategy-research check-data` 对显式指定区间检查并保存快照，不调用模型、不计算收益。原始行情、采集／清洗、单项诊断接口保持通用；任意日期输出不能单独证明正式研究准入。模拟账户接入、跨任务自动暴露汇总和滚动验证未在这次接口修改中实现。

**原库处理补充：** 用户随后授权对已发现的 BTC/ETH 现货和标记价格缺口直接线性插值写入原库。记录见[小时行情插值处理记录](小时行情插值处理记录.md)。这些数据使用未来真实端点，是事后估算；底层名义时间戳不代表插值当时可得，不能将补齐后的回测称为完整因果重放。新研究用途记录明确携带此处理说明。
