# 全创意卡池组合研究

入口扫描整个 `experiments/idea_pool`，保留每份记录的准入、拒绝、重复或错误状态及原因。当前卡片合同要求冻结公式与方向、通过期限、B验证和准入证据；已有原档只提供现货/永续小时K线、标记价和原生资金费相关字段。未平仓量、交易者比例、指数价、溢价及清算字段没有在本数据集中恢复，依赖这些字段的卡保留为不可执行记录。

卡片按通过的1h、4h、24h期限和字段集合分组。同一信号用展开公式与方向识别，期限是评估属性。结构家族只合并相同运算结构的窗口变体；方向、其他常数和运算顺序保留。代表按最短回看期、完整ID选择，完全不使用收益、IC大小或C表现。所有成员快照、源文件字节哈希、规范化内容哈希及代表映射均保存。

## 本轮预定实验

每个期限先运行所有可执行结构家族代表的等权基准，然后按固定家族ID顺序交错划分四个块，逐块移除。每个家族进入一个块，最多新增12项组合实验。全池与移除块的差值也表示把该块加回的配对增量，剩余因子重新等权；该结果只归因于整块，不拆成成员的独立贡献。每个策略另跑两倍手续费与滑点的成本压力测试，这些账户运行也会保存。

每个币、每个小时至少80%的选中因子有标准化值时才生成分数，可用因子按等权均值合成，不填补缺失。一个因子缺值不会直接使整个卡池该行失效。同一期限所有预定方案共享覆盖阈值掩码和完整账户网格；C延续同一掩码定义，即使只执行其中一个候选和全池参考。逐行可用因子数、各方案覆盖与共享覆盖单独保存。

1h、4h、24h分别按1、4、24小时调仓。账户沿用固定十币、两多两空、总敞口80%、单币上限20%、手续费10bps、滑点5bps、初始资金10,000的规则。资金费按用户确认，用事件前最后一根完整原始分钟标记价close估算结算价，最大年龄60秒。

三个等权基准和所有新方案一起按A+B净收益、较低回撤、排序卡片ID、期限确定唯一候选。冻结后只运行该候选所属期限的C账户、全池参考与成本压力；C不回传搜索、不重新选组合。A+B和C均要求净收益及两倍成本收益不低于零、回撤不超过15%、至少一个成交调仓时点。未通过时保存诊断结果，不启动前向账户。

## 运行

```sh
.venv/bin/python -m crypto_quant.cli strategy-research pool-run \
  --contract examples/strategy_research/multifactor/pool/contract.json \
  --output experiments/strategy_research/pool_20261003
```

此入口是确定性全池研究，不调用模型。计算和账户复用现有引擎；全池两两相关没有计算，空相关表明确表示未计算。它没有穷举组合，也没有将每张卡都当成一个独立策略逐一筛选。

运行目录包含逐条 `catalogs/`、全部可执行成员 `cards/`、数据/代码版本、访问行情面板前冻结的 `plan.json`、各期限A+B账本、可用因子计数、块增量、候选冻结、C账本以及总报告。相同运行ID拒绝覆盖。每个已完成阶段单独保存；失败留下现有证据，不自动重试或切换主库。

正式运行另存 `execution_source/` 的实际Python源码、项目依赖定义，以及逐文件哈希和运行环境版本，能在源码继续改动后取回这一版。此前四卡运行保留了账本和源码哈希，但没有单独保存当时未提交的源码；其源码恢复限制不能由新快照补回。

本轮A+B为UTC `[2022-08-01,2025-08-01)`，C为 `[2025-08-01,2026-08-01)`。A/B已参与因子选择，C也曾暴露，结果属于内部历史研究。来源完整性及固定币池元数据预检覆盖C，但C行情面板和账户结果计算发生在候选冻结后。历史发布/接收延迟未认证；当前资金费结算价是已披露的估算。

## 2026-10-03 已完成结果

扫描270份记录，92张不同卡在现有原档下可执行。1h/4h/24h分别有50/48/53张准入，使用46/47/53个结构家族代表；期限计数有重叠。三个基准及12个块移除共15个A+B方案全部未过门槛。

冻结的最高排名方案 `h24-remove_block_01` 包含39张代表卡：A+B净收益−64.43%、最大回撤69.59%；C净收益−21.87%、最大回撤24.13%，两倍成本C收益−51.39%。C全池参考净收益−15.66%，块移除在C落后参考；保持冻结方案，不据此重选。没有启动前向或Paper。

相关14个测试文件通过124项测试、48个子测试，34份实际账本的净值、回撤、费用、滑点、资金费与换手独立复核一致。完整结果见[研究报告](/Users/stellan/量化投资/experiments/strategy_research/pool_20261003/multifactor-pool-20261003/report.md)与[验证记录](/Users/stellan/量化投资/experiments/strategy_research/pool_20261003/multifactor-pool-20261003/verification.md)。

## 对称正交化与滚动 ICIR 升级

`pool-run` 的 `schema_version=2` 使用新合同 [icir.contract.json](../../examples/strategy_research/multifactor/pool/icir.contract.json)。以上已完成结果及 `schema_version=1` 合同仍对应等权版。新版实现可执行，完整历史结果须通过新的运行取得。

每个小时先按卡片原始冻结方向做横截面标准化，再在全体方案共享的完整因子截面上，分别对各子集重新中心化并计算对称正交化。若中心化矩阵为 `X`，变换为 `X (XᵀX/n)^{+,-1/2}`。使用 SVD 和机器精度秩阈值计算伪逆平方根，不加岭项、不按列顺序逐一回归，也不填补缺失因子。

当前10币池的中心化有效秩最多为9，低于各期限的因子数。伪逆变换保留有效特征子空间；秩不足时变换后的协方差为投影矩阵，全部原因子列无法同时两两正交。`cross_sections.csv` 保存每小时币数、因子数、有效秩和状态。

每个正交化因子计算与该期限一致的下一开盘至 `h` 小时后开盘收益的截面 Spearman Rank IC。信号时间戳 `t` 标记当前小时开盘；历史信号 `u` 的标签在 `u+h+1h` 才成熟。当前权重只使用标签终点不晚于 `t` 的IC，防止使用本次成交开盘及之后的数据。

窗口固定为最近720个小时，至少168个有效IC；`ICIR=mean(IC)/std(IC, ddof=1)`，不年化。每小时计算 `wᵢ=|ICIRᵢ|/Σ|ICIR|`，负ICIR对应的正交化因子分数同时乘−1，再合成为资产分数。原卡片方向仍保存在卡片中，滚动方向另存 `directions.csv`。历史不足、IC未定义或IC方差为零的因子权重为零；所有权重都为零时没有分数，计划调仓转为空仓。

新版要求 `minimum_available_factor_share=1`，替代等权版的80%可用因子均值规则。至少3个币的全部因子共同有效才计算截面；缺失行保留为空。组合子集共享同一完整因子掩码，但各自使用自己的正交化矩阵、ICIR与权重。`shared_signal_coverage` 记录因子共同覆盖；`account_score_available_rows` 和 `sample.account_signal_rows` 分别记录真正有分数的资产行数和小时数，避免把冷启动计作已有交易信号。

C候选与全池参考读取所属期限A+B保存的尾部正交因子和原始开盘价，接续完整滚动窗，并在跨边界标签成熟后使用它们。重叠开盘价必须一致；不补数据、不重新选择候选。C使用已冻结的加权算法按小时更新权重，这是预定策略的一部分。

```sh
.venv/bin/python -m crypto_quant.cli strategy-research pool-run \
  --contract examples/strategy_research/multifactor/pool/icir.contract.json \
  --output experiments/strategy_research/pool_icir_20261003
```

各阶段 `combination/<方案>/` 保存 `orthogonalized.csv`、`cross_sections.csv`、`rank_ic.csv`、`mature_ic_count.csv`、`icir.csv`、`weights.csv`、`directions.csv` 及跨段历史快照；`score_policy.json` 和总 `plan.json` 保存计算与时序政策。手续费、滑点、资金费、排序选币、块预算和准入门槛沿用原账户规则。

## 四组消融实验

独立入口 `ablation-run` 按每个期限固定同一批结构家族代表，执行以下四组：

| 组别 | 因子处理 | 加权 |
|---|---|---|
| A | 原版方向标准化、不正交 | 等权 |
| B | 原版方向标准化、不正交 | 30天滚动ICIR |
| C | 对称正交化 | 等权 |
| D | 对称正交化 | 30天滚动ICIR |

控制相同卡池、完整截面、ICIR就绪时点、资产名额、调仓周期、初始资金、手续费、滑点和资金费。四组共享所有组可生成分数的交集；A组在配对样本上重新运行，因此与旧版80%覆盖样本的收益数值不要求相同。B/D的权重方案均包含负ICIR时翻转方向，四组对照不单独区分权重幅度与方向翻转的作用。

1h/4h/24h各自运行A+B历史开发和C内部验证，全部四组在读取行情前预定。合计24个基础成本账户与24个两倍成本账户；C接续相应B/D滚动历史，各账户独立从10,000开始。所有组都进入C，运行不搜索子集、不按C重新选组。

```sh
.venv/bin/python -m crypto_quant.cli strategy-research ablation-run \
  --contract examples/strategy_research/multifactor/pool/ablation.contract.json \
  --output experiments/strategy_research/ablation_20261003
```

每个期限、每个阶段保存四组完整账本、完全一致的信号可用掩码、原始与正交因子面板及B/D滚动权重。总报告与`comparison.csv`列净收益、回撤、Sharpe、换手和成本压力。`result.json`另列B−A、C−A、D−C、D−B、D−A、交互项D−B−C+A及两项平均主效应，基础成本和压力成本均计算。差值是固定历史账户表现的配对比较。

### 2026-10-03 消融结果

48个账户全部完成，184项测试、90项子测试通过；实际账本的现金/净值、仓位、费用、资金费、收益、回撤、Sharpe以及四组信号掩码独立复核通过。

| C内部验证净收益 | A 不正交+等权 | B 不正交+ICIR | C 正交+等权 | D 正交+ICIR |
|---|---:|---:|---:|---:|
| 1h | 约−100% | 约−100% | 约−100% | 约−100% |
| 4h | −58.50% | −56.59% | −62.51% | −67.77% |
| 24h | −16.34% | −7.67% | −16.47% | −24.93% |

B在C段4h和24h分别比A改善1.91、8.67个百分点，但24h的A+B反而下降8.44个百分点。D在4h、24h的两个阶段均最差，当前对称伪逆正交化没有提供稳定净收益增益；全部基础及两倍成本账户仍亏损。

## 信号触发调仓

`rebalance-run` 复用上述四组消融实验中 B 组已经保存的信号、行情和资金费，固定不正交＋滚动 ICIR，只改变调仓方式。输入先复制并校验 SHA256，规则在读取账户结果前冻结。

| 组别 | 检查周期 | 排名缓冲 | 仓位缓冲 |
|---|---|---|---|
| R0 | 原来的 1h／4h／24h | 无 | 无 |
| R1 | 每小时 | 无 | 无 |
| R2 | 每小时 | 有 | 无 |
| R3 | 每小时 | 无 | 有 |
| R4 | 每小时 | 有 | 有 |

每边最多两个币；新多仓须进入前两名，新空仓须进入后两名；有排名缓冲时，已有仓位分别留在前四名、后四名内即可继续持有。先保留符合条件的旧席位，再补充空位，旧仓不被新候选自动挤走。排名并列按币种名排序；补位时多头先行，并排除已有空头。入场排名使用全体有效币，冲突或币种不足导致的空位留作现金。信号缺失时退出对应仓位。

仓位缓冲为 2 个百分点。当前配置新仓开到 20%，已有仓在 18%～20% 区间内保持合约数量完全不变；低于区间加仓至 18%，高于区间减仓至 20%。退出直接归零。总敞口 80%、单币 20% 的限制优先于缓冲。决策使用信号收盘时的净值与价格，执行开盘的资金费由旧持仓支付；成交成本、价格跳空和随后行情会让实际敞口继续漂移。

每组基础成本、两倍成本各自读取本账户的持仓和净值作决策。先完成 24h，再应用相同冻结规则到 4h、1h；预测期限和每小时检查频率分开。原定时入口保留用于复现与对照。

```bash
.venv/bin/python -m crypto_quant.cli strategy-research rebalance-run \
  --contract examples/strategy_research/multifactor/pool/rebalance.contract.json \
  --output experiments/strategy_research/rebalance_20261003
```

每个账户保存订单、成交、持仓、资金费、账本，以及 `decisions.csv`（排名、实际/目标仓位、动作与原因、数量、成交成本）、`turnover_categories.csv`（换币、方向反转、比例微调）、`monthly.csv`。R0逐项对照原B组订单、成交、账本；报告同时比较净收益、毛盈亏拆分、风险、成本、持有时间和实际敞口。C段继续作为已暴露的内部历史比较。

账户接口 `run_perpetual_account(..., targets=None, scores=hourly_scores, rebalance_policy=RebalancePolicy(...))` 可直接使用按实际持仓决策的调仓规则；原来传入固定 `targets` 的接口继续支持原版复现。

### 2026-10-03 调仓对照结果

60个账户全部完成，60项相关回归测试通过。原版R0的六个基础/压力账户逐项复现原B组订单、成交和账本，数字误差均为0。

| C内部历史比较 | 原版净收益 | 双缓冲净收益 |
|---|---:|---:|
| 24h | −7.67% | −20.76% |
| 4h | −56.59% | −19.84% |
| 1h | −99.99961% | −99.95698% |

双缓冲在4h两个阶段均改善表现，C段换手减少约62%；24h两个阶段均弱于原版；1h仍接近耗尽净值。全部方案未通过现有门槛，新规则作为可运行的研究模式保留。
