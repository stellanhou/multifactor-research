# 多因子传统基线使用说明

传统基线把已冻结的 FM-v6 创意卡接入确定性因子处理、排序组合和 USD-M 永续账户回放。运行不调用 Agent，也不会修改创意卡的上游状态。

## 运行

在仓库根目录执行：

```sh
.venv/bin/python -m crypto_quant.cli strategy-research baseline \
  --contract examples/strategy_research/multifactor/contract.json \
  --db market_data/crypto_quant.sqlite \
  --output experiments/strategy_research/multifactor_v1
```

合同中的 `cards` 和 `universe` 相对合同文件所在目录解析。运行目录是 `<output>/<run_id>/`；目录已存在时命令会失败，避免覆盖此前结果。要运行新的配置，应先冻结新合同并使用新的 `run_id`。

当前示例用 3 张通过 24 小时期限的卡、固定 10 币池，在 2025-09-01 至 2025-09-15 进行工程回放，预热 168 小时。该区间已经暴露并属于历史内部验证样本；候选卡的历史重检结果用于规则选择，因此本例用于核对流程与账本，不构成独立样本外或前向证据。

## 合同与比较口径

合同冻结用途、历史阶段、半开账户区间 `[start, end)`、预热长度、目标期限、卡片路径、显式币池、已知历史数据用途、数据处理说明、交易成本和组合规则。首版仅接受 `purpose=engineering`。输入读取不修改数据库，也不自动填补行情。数据处理说明须结合运行产物中的数据溯源文件阅读。

每张卡按其声明方向处理，在每个 UTC 小时的可交易横截面做总体标准化（`ddof=0`）。因子覆盖和逐时 Spearman 相关会保存下来；相关汇总同时保留绝对相关和分位数，供检查不同阶段的关系变化。相关系数不会自动删除卡片。

首版要求冻结币池中的每个资产在整个账户区间都有完整的永续成交价与标记价格，即使某小时成员资格为假也一样。成员掩码控制选币资格；缺少执行或估值报价会停止运行。尚不支持缺报价的上市、退市过程。因子面板及相关诊断覆盖整个输入区间（含预热），账户比较的覆盖口径只计入实际可执行信号窗口。

基线运行以下组合：

- 每张卡的单因子组合。
- 所有卡片等权的组合。
- 逐一移除一张卡，并将剩余卡片重新等权的消融组合。

所有组合都使用全体因子的共同有效掩码，包括单因子和逐一移除实验。每个计划调仓时点若共同样本没有有效分数，则该时点的目标仓位为空；空信号小时仍完整保留在信号网格中。覆盖报告将预热期与账户信号窗口分开，显示共同样本造成的覆盖变化。

因子分数按固定名额排序生成多空目标，权重上限、总敞口和调仓周期均由合同给定。bar-open 时间表示该 bar 的收盘信号；信号在下一小时开盘执行。信号窗口为 `[start-1h, end-1h)`，最后一根行情只用于账户末值估算，不会产生在合同结束后成交的信号。各实验独立从合同初始资金开始，并记录手续费、滑点、资金费和保证金检查。成本压力情景只对等权组合运行，将合同中的手续费和滑点倍数应用于交易费用，资金费仍使用同一组历史事件。

账户按连续合约数量和完全成交估算，采用线性 USDT 保证金损益及固定基点滑点；不模拟交易所最小数量、部分成交、强平或日内路径。它是可核对的研究账本，不是交易所清算模拟器。

## 运行产物

每次运行保存以下内容：

- `contract.json`、`data-usage.json`：本次冻结合同和数据使用边界。
- `cards/`、`cards.json`：卡片源文件快照、哈希及选卡清单。
- `inputs/`：因子输入面板、币池、逐币行情、资金费事件和数据溯源诊断快照。
- `factor_panels/`：原始因子、标准化因子、有效掩码、共同掩码、覆盖、逐时相关及相关汇总。
- `coverage_impact.csv`：各卡自身覆盖与全因子共同样本覆盖，含预热和账户窗口口径。
- `experiments/`：每个单因子、等权及消融目录均含 `signals.csv`、`targets.csv`、`orders.csv`、`fills.csv`、`funding_events.csv`、`positions.csv`、`ledger.csv` 和 `metrics.json`。等权另有 `equal_weight_stress/` 成本压力结果。
- `result.json`、`report.md`：确定性运行状态、Git 与源文件版本、各组合指标及相对等权的指标变化、结果入口和中文摘要。

工程完成只说明输入检查、因子计算、组合生成及账户回放已成功执行。收益为负或消融没有增量仍是有效的工程结果；这不会自动证明策略有效，也不会启动前向验证或发布策略。
